# Instruções do projeto

- Após qualquer alteração solicitada pelo usuário, execute os testes relevantes, crie um commit e envie a atualização para `origin/main`.
- Quando houver uma nova versão portátil, publique o `.exe` em uma GitHub Release; não adicione executáveis ao histórico Git.
- Nunca envie `.env`, credenciais, chaves de API, capturas, diagnósticos privados, estado de sessão, dependências ou artefatos de build.
- Preserve o proxy Gemini separado e mantenha a chave da API somente no serviço.
- Descubra menus, links internos, abas e formulários Novo/Nova em qualquer sistema web, sem regras ligadas a um produto específico.
- Nunca salve, exclua, envie, publique, aprove, pague ou confirme alterações durante a varredura.
